评测方案 · v1.3 · 2026-11-17

WeKnora 知识库评测：一页看懂版

这套评测只做一件事：给每个业务问题准备两个“标准答案”——一个标准访问路径，一个标准知识集合。然后调用 MCP，看它有没有按路径走、有没有把知识集拿全。

不是评页面排版 不是评聊天体验 评 MCP 的取数行为 9 组案例对应评测维度

01 先看结论 评测思路只有三步

1. 出题选真实业务问题，业务专家标出必须拿到的所有页面。
2. 调 MCP像 AI Agent 一样逐步调用，不直接看最终答案。
3. 对路径是否先索引/摘要，再按需下钻，没有跳级或倾倒。
4. 对集合必须返回的知识有没有缺、旧版本有没有混进来。
5. 出结论缺致命知识、层级违规或越权，直接不通过。

一句话：渐进式披露评“怎么拿”，知识完整性评“拿到了什么”。两条都对了，基于 WeKnora 的知识库才算正确。

02 两个评测面 分别看什么内容

两个评测面不要混在一起：一个检查 Wiki 结构有没有被 MCP 正确、克制地使用；另一个检查输入对应的相关知识有没有被拿全。

评测面 A：Wiki 结构正确性

通俗解释：Wiki 是否像一棵能被 AI 正确行走的树——先找对入口，再看目录和摘要，最后按需打开详情。

维度检查内容
W1 入口路由能否识别产品线、业务域、当前基线和入口页。
W2 层级顺序是否按空间入口 → 域首页 → 域上下文包 → 详情页 → 证据页逐层读取。
W3 返回粒度目录层不返回正文，摘要层不替代精确规则，详情层才返回完整规则。
W4 下钻指引每层是否给出 page_id、next action 和继续下钻的条件。
W5 停止条件问题已足够回答时是否停止；是否遵守最大自动展开页数。
W6 状态治理confirmed / active、旧版本、冲突、废弃、权限是否处理正确。

评测面 B：检索知识准确性

通俗解释：给定一个业务输入，MCP 返回的知识集合是否覆盖所有会影响结论的内容。

维度检查内容
R1 输入理解能否识别同义说法、业务对象、意图和缺失条件。
R2 主知识召回主规则、主定义、主场景是否必然返回。
R3 关系召回例外、术语、流程、状态、风险、依赖、证据是否一起返回。
R4 条件触发出现积分、虚拟商品、预售、并发等触发词时，是否带入对应知识。
R5 干扰排除无关页面、重复内容、旧版本、无权限内容是否被排除。
R6 深度适配返回的是摘要、详情还是证据，是否足以支撑当前任务。

区别：评测面 A 发现“读法错”，例如跳级、倾倒、无下一步；评测面 B 发现“读漏 / 读错”，例如漏例外、漏跨域、混入旧版本。

03 案例集设计 每组案例只测明确维度

MVP 共 30 题，分成 9 组。每组案例都绑定上面的 W/R 维度，避免所有指标混在一道题里导致失败原因看不清。

案例集 题量 匹配维度 典型题目 通过标准
A1 入口路由3W1“预售退款”应进入商城 / 订单域，而不是营销或会员域。首次返回正确空间、业务域和入口指针。
A2 层级与粒度4W2 / W3先问“订单域有哪些退款知识”，再问“48 小时规则原文是什么”。第一问只给索引 / 摘要，第二问才下钻详情。
A3 下钻与停止4W4 / W5从域上下文包继续打开预售退款场景；取完必读页后停止。next action 可用，不超最大展开数，不主动倾倒证据。
A4 状态与权限3W6v2.0 与 v2.3 并存、冲突页、跨产品线访问。只返回当前有效版本；冲突先读证据；无权限安全拒答。
B1 单点事实4R1 / R2“待履约是什么意思”“退款超时是多少小时”。返回正确术语或主规则，并达到详情层。
B2 规则与例外5R2 / R3预售、虚拟商品、用户主动取消等例外场景。主规则和所有必选例外同时返回，缺一个即失败。
B3 流程与风险3R3 / R6下单到退款状态流转、并发回调、重复退款。返回流程、状态前置后置和风险控制知识。
B4 跨域条件2R4退款时提到积分回退、财务对账。触发对应跨域决策页，而不是只返回本域页面。
B5 负例与噪声2R5库里没有的问题、权限外问题、同名但无关的知识。拒答或提示条件不足；不混入无关和越权内容。

扩展规则：发版评测可把每组按产品线扩展到 90-120 题；线上失败问题按同一维度归入对应案例集，不新增口径混乱的自由题。

04 一个完整例子 看懂这个就看懂评测

题目：AI 要补充“预售订单未发货前申请退款”的需求说明。业务专家不能只给一个标准答案，还必须说明这题需要哪些知识，以及 MCP 应该怎么拿。

业务专家预先写好的两个标准答案

标准路径：怎么拿
  1. 先识别到「商城 / 订单域」，只返回域入口和状态。
  2. 再取订单域上下文包，只返回摘要和必读清单。
  3. 需要精确规则时，才展开具体页面。
  4. 涉及积分回退时，才跳到跨域决策页。
  5. 只有冲突或需要核验来源时，才打开证据层。
标准集合：拿到什么
  • 预售订单退款场景
  • 退款超时规则
  • 取消订单规则
  • 虚拟商品退款例外
  • 重复退款风险
  • 条件知识：积分回退跨域决策

实际评测时的判定

检查合格行为典型不合格
路径检查第 1 次返回域入口 / 摘要，后续按需打开页面。第 1 次直接返回几十段原文；或只给摘要却让它输出精确规则。
集合检查标准集合中的 5 个必读页面都进入返回结果。只返回“预售退款场景”，漏掉虚拟商品例外和重复退款风险。
条件检查用户提到积分回退时，返回跨域决策。返回会员积分入账规则，但没返回退款与积分回退口径。
版本检查只返回当前 active / confirmed 版本。把 v2.0 旧规则和 v2.3 当前规则一起当成有效规则。

为什么这样评？如果只看最终答案，模型可能碰巧答对，但漏掉例外和风险；下次生成需求时仍会出错。评测 MCP 取数过程和取数集合，才能定位问题在知识库、检索还是披露协议。

05 每道评测题长什么样 五个字段就够了

先不引入复杂指标。评测集只要把下面五个字段写清楚，就能自动判分。

题目： 预售订单未发货前申请退款，需求说明要注意什么？ 1. expected_path：标准访问层级 D0 空间入口 → D1 订单域索引 → D2 域上下文包 → D3 必读页面 2. required_pages：必选页面，缺一个就失败 - 场景-预售订单退款 - 规则-退款超时 - 规则-取消订单 - 需求-虚拟商品退款例外 - 风险-重复退款 3. conditional_pages：条件页面 - 提到“积分回退”时，必须加：决策-退款与积分回退口径 4. forbidden_pages：禁止返回 - 旧版本页面 - 无关产品线页面 - 无权限页面 5. stop_condition：什么时候停止展开 - 必读页面取完即停；未涉及积分或冲突，不打开证据全文

06 两张评分表 先定性，再量化

评分 A：渐进式披露是否正确

只看 MCP 的访问过程，不看答案文笔。

检查分值
W1 入口路由：从正确的空间 / 域入口开始15
W2/W3 层级与粒度：先索引摘要，再按需详情25
W4 下钻指引：提供 page_id / next action20
W5 停止条件：有理由才展开，取完即停20
W6 状态治理：版本、冲突、权限正确20

评分 B：相关知识是否拿全

只比较实际返回集合和标准集合。

检查分值
R1/R2 输入理解与主知识召回35
R3 例外、术语、流程、风险等关系覆盖25
R4 条件页面该触发时触发15
R5 无关页面、旧版本、越权内容不混入15
R6 返回深度和来源定位足够核验10

推荐门槛：MVP 阶段两张表都 ≥90 分；必选知识召回 ≥95%；任何一题缺主规则、关键例外、当前版本或越权返回，均一票否决。

07 MVP 怎么跑 30 题，5 天

30 题直接来自第 03 章的 9 组案例集：A1-A4 共 14 题评 Wiki 结构读取，B1-B5 共 16 题评知识准确性。

五天安排

时间做什么产出
D1业务专家出题30 题、标准路径、必选 / 条件 / 禁止页面。
D2固化环境知识库快照、模型配置、MCP schema、权限账号。
D3批量调用每次请求、返回页面、层级、token、trace。
D4自动对比 + 人工复核路径违规清单、漏召回清单、混入清单。
D5归因和结论P0/P1 修复项、回归用例、是否通过。

08 出错后怎么定位 四类原因

知识库没写对

  • 页面缺失。
  • 例外、风险、跨域关系没登记。
  • 状态或版本标错。

披露协议没实现对

  • 缺少层级控制。
  • 默认返回全文。
  • 没有 next action。

检索没找全

  • 向量召回不足。
  • 精确编号没走 BM25。
  • 过滤条件过严。

排序或过滤错了

  • 旧版本排前面。
  • 无关内容混入。
  • 权限过滤没在检索层执行。

修复原则：先补知识关系和元数据，再调检索参数；不能只调大 top_k 或让模型凭感觉补答案。
