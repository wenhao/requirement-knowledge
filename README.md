# 软件需求 AI 知识库文档中心

本仓库沉淀软件需求领域 AI 知识库的调研证据、建设方案、质量评测、AI Coding / SDD 适配方案、模板与完整示例。目录按知识库建设生命周期组织，避免研究底稿、落地方案、质量标准和示例资产混放。

## 目录结构

```text
requirement-knowledge/
├── 01-调研/                  # 研究底稿与外部证据
├── 02-知识库建设/             # 总体方案、Wiki 结构、WeKnora 落地
├── 03-质量评测/              # 知识库正确性与 MCP 行为评测
├── 04-AI-Coding与SDD/         # 需求 AI 就绪度、路由与试点样例
├── 05-模板与示例/             # 可复用模板、目录规范、完整知识库样例
└── README.md                 # 仓库入口与阅读路径
```

## 推荐阅读顺序

1. **全景调研**：阅读 [`01-调研/人工智能知识库建设方法与开源框架产品调研-v5.md`](01-调研/人工智能知识库建设方法与开源框架产品调研-v5.md)，建立 RAG、LLM Wiki、上下文工程与产品格局地图。
2. **空白验证**：阅读 [`01-调研/人工智能知识库六大空白点细分调研.md`](01-调研/人工智能知识库六大空白点细分调研.md)，检查关键争议是否有新证据。
3. **建设方案**：阅读 [`02-知识库建设/软件需求人工智能知识库建设方案-v1.3.md`](02-知识库建设/软件需求人工智能知识库建设方案-v1.3.md)，确定场景、架构、路线图与 WeKnora 交付方式。
4. **Wiki 落地**：阅读 [`02-知识库建设/需求Wiki结构设计-v1.0.md`](02-知识库建设/需求Wiki结构设计-v1.0.md)，将方案细化为目录、模板、披露协议与学习旅程。
5. **质量评测**：阅读 [`03-质量评测/WeKnora知识库正确性评测方案-v1.3.html`](03-质量评测/WeKnora知识库正确性评测方案-v1.3.html)，用“标准访问路径 + 标准知识集合”验证 MCP 渐进式披露与相关知识完整性。
6. **工程适配**：阅读 [`04-AI-Coding与SDD/AI Coding与SDD需求适配与落地方案-v1.8.md`](04-AI-Coding与SDD/AI%20Coding与SDD需求适配与落地方案-v1.8.md)，判断需求适合 AI Coding 还是先走 SDD。
7. **试点对照**：阅读 [`04-AI-Coding与SDD/SDD试点Spec样例-优惠券叠加规则-v1.8.md`](04-AI-Coding与SDD/SDD试点Spec样例-优惠券叠加规则-v1.8.md)，对照完整 SDD 试点写法。
8. **模板对照**：阅读 [`05-模板与示例/首页索引与域上下文包完整示例.md`](05-模板与示例/首页索引与域上下文包完整示例.md)，理解 `_index.md` 与 `_domain-context.md` 的职责边界。
9. **完整样例**：阅读 [`05-模板与示例/需求知识库完整示例/首页.md`](05-模板与示例/需求知识库完整示例/首页.md)，查看覆盖 L0-L4 披露层级的需求知识库样例。

同名 `.html` 文件是对应 Markdown 的浏览版；评审时以 Markdown 为准。

## 命名与归档规则

- 新文档使用简体中文命名，版本号放在文件名末尾；目录名用两位数字前缀表达阅读阶段。
- 研究证据进入 `01-调研/`；知识库建设方案进入 `02-知识库建设/`；评测方案与回归资产进入 `03-质量评测/`；AI Coding / SDD 方案进入 `04-AI-Coding与SDD/`；模板和示例进入 `05-模板与示例/`。
- 同一文档的 Markdown 与 HTML 导出保持同名，仅扩展名不同。
- 新版本优先在同文件内更新版本号；确需保留旧版时，在对应一级目录下建立 `历史版本/` 并按日期归档。
