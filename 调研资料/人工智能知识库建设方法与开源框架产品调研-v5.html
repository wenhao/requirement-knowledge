01

核心结论（SCQA）

Executive Summary
S情境
企业普遍要用 LLM + 私有知识构建 AI 知识库。2023-2024 年 RAG 是唯一答案，2025 年生成式 LLM Wiki 路线兴起，2026 年 Agent 记忆与上下文工程成为第三股力量。
C冲突
①单一向量检索在多跳推理、全局理解上结构性失灵；②"长上下文杀死 RAG"论战虽已收敛，但 Context Rot（输入越长性能越差）刚被 18 个前沿模型实测证实；③产品从四层数十个膨胀为八层 150+，且出现"归档潮"，Star 数与可用性脱钩；④RAND 统计 80% 企业 AI 项目失败率——工程方法比工具选型更致命。
Q问题
AI 知识库到底该怎么建、怎么选、怎么活过 90 天？
A答案
三线分流（检索找答案、编译沉淀知识、调度管上下文，MCP 互访）；检索式按混合架构+查询分诊演进；成败在数据治理与运营；选型必须带生命周期意识。
判断一
三线叙事并存且加速融合。WeKnora（三模式一体）、OpenViking（上下文数据库）、MemOS（记忆操作系统）分别代表三线的产品化形态——"检索找答案、编译沉淀知识、调度管上下文"成为企业知识中枢三件套。 WeKnora · OpenViking · MemOS
判断二
Long-Context 之争已收敛：<200K token 全塞、200K-2M 看并发成本、>2M 必须 RAG；Context Rot 实测证伪"全量塞上下文"。"RAG 定位 5000 相关 token，长上下文负责在其上推理"。 codefarm · xqa.io
判断三
2026 组件层代际更替：嵌入/重排进入 Qwen3 时代（Reranker 全面超 bge 系）；ColPali 免 OCR 视觉检索工业化；图谱+向量融合库冲击双组件架构；pgvector 生态固化。 Qwen 博客 · ColPali
失败教训
成败在数据治理与运营：法律公司 18 万合同 RAG 因嵌入缺结构元数据失败，重建后覆盖率 100%→87% 主动降换正确性；金融客服 3 个月不重索引致升级率 +34%。 复盘
生命周期警示
选型必须查最近提交：h2oGPT · Verba · Reor · Vanna（23.8k★ 但只读）· pgvecto.rs 已归档；Microsoft GraphRAG、STORM 维护放缓——Star 数与可用性已脱钩，采购前以官方仓库当日状态为准。

技术全景：三线叙事

Three Paradigms

三条建设路线

维度检索式（RAG 系）生成式（LLM Wiki 系）上下文工程 / Agent 记忆系
核心动作查询时检索原文片段，交 LLM 组织答案入库时 LLM 主动编译资料为互链 Wiki知识当一等资源存取调度（压缩/笔记/子代理/JIT 加载）
知识形态向量索引+分块原文主题文章+反链+索引记忆立方（明文/KV/参数三态）、分层记忆管线
基础设施向量库+embedding+检索管线Markdown 目录+大上下文 LLM记忆引擎+上下文数据库+MCP
规模边界大规模企业数据集个人到部门级（约 10 万-100 万词）会话级到组织级（跨会话/跨 Agent）
代表Dify / RAGFlow / FastGPT / MaxKBKarpathy LLM Wiki、STORM、WeKnora WikiMem0、Letta、MemOS、OpenViking、TencentDB Agent Memory

三线不互斥且加速融合——检索找答案、编译沉淀知识、调度管上下文，正成为企业知识中枢的三件套。

检索式：五代 RAG + 推理增强新变量

范式核心机制成熟度
Naive RAG索引→检索→生成单次流水线2023 标准，2025 起不适合生产
Advanced RAG检索前优化（改写/HyDE）+ 检索后处理（重排/压缩）2024 起生产主流
Modular RAG可插拔模块：路由/记忆/融合/任务适配企业差异化场景
GraphRAG知识图谱+向量双检索2024 提出，2026 生产可选
Agentic RAGAgent 自主规划：迭代/反思/纠错/多智能体2026 企业主流形态
推理增强检索（新）推理链中途检测知识缺口动态触发检索（Search-o1 / Search-R1 / ReaLM-Retrieve）论文最热方向；工业以 prompt 级 agentic 检索为主

性能量级：Agentic RAG 复杂查询准确率 +47%、多部分问题完整度 +63%（LlamaIndex 基准）；代价是 3-7 次 LLM 调用/查询、8-15 秒延迟、成本约 4 倍。Search-o1 多跳 +30%；ReaLM-Retrieve +10.1% F1 且检索调用 -47%。

生成式：Karpathy LLM Wiki 四阶段

  • 摄取 Ingest —— 网页/论文/仓库转 Markdown 入 raw/ 目录（人类唯一大量介入的环节）
  • 编译 Compile —— LLM 增量编译为互链 Wiki：约 100 篇/40 万字 + 总索引 + 反链 + 派生幻灯片/图表
  • 查询增强 —— 问答 Agent 跨文章回答复杂问题，答案回写 wiki："每次探索都累积"
  • 体检 Lint —— LLM 扫描不一致、经 web 搜索补缺失、发现新概念关联——知识库自愈

关键实测：约 40 万词内复杂问答几乎不需要 RAG——"向量检索是大锤，结构化 Markdown 是手术刀"。STORM（斯坦福，~31.5k★）自动维基写作（组织性 +25pp），注意维护放缓（最后发版 2025-01）。2026 年扩展：Open Notebook（~40k★，自托管 NotebookLM 平替）、Obsidian 官方 obsidian-skills（~50.2k★，教 Agent 操作 Vault）。

第三线：上下文工程与 Agent 记忆

Anthropic《Effective context engineering》（2025-09）确立四技术：Compaction 压缩、结构化笔记（NOTES.md）、子代理架构（回传 1-2K token 摘要）、Just-in-time 加载；Claude memory tool 实测 agentic search +39%、token 消耗 -84%。MemOS 把记忆当一级资源：MemCube 三态（明文/KV-cache/LoRA 参数）+ 调度器。企业姿势——文档知识走 RAG 管线治理，行为知识走记忆管线沉淀，两者通过 MCP 互访。

建设方法与组件选型

How to Build

检索式五步建设法

步骤要点高频陷阱
① 数据治理盘点知识源、清洗（约 40% 工作量）、权限矩阵（检索层过滤）新旧版本混存"答旧不答新"（银行 2019 利率案例）
② 解析切分版面级解析（MinerU/DeepDoc/PaddleOCR）；语义切块 300-500 字+表格整块；父子分块512 token 定长切断"不保本"警示；嵌入缺结构元数据（法律案例根因）
③ 索引检索BM25+向量+RRF；cross-encoder 重排；嵌入选型"榜单圈定+自测 Hit@3"歧义查询："Apple"命中率 38%→82% 靠 BM25+标签过滤修复
④ 评测校验50-100 条起步→200-500 条成熟；RAGAS+DeepEval+promptfoo 进 CI/CD；RAGChecker 诊断"检索错还是生成错"评测集由工程师而非业务专家构造
⑤ 接入运营真实入口+转人工兜底；反馈回流；增量更新管道；90 天分水岭向量库 3 个月不重索引→引用过期（升级率 +34% 案例）

GraphRAG 决策与 Agentic 铁律

  • 四阶段流水线：实体关系抽取（去重/消歧）→ 图谱构建（Neo4j/NebulaGraph + Leiden 社区）→ 查询路由（事实型走向量、关系型走图）→ 上下文组装（区分结构化事实与原文片段）
  • 实施路线：基线向量 RAG（1-4 周）→ 图谱构建（5-10 周/50 万文档）→ 混合路由（11-13 周）→ 生产调优（14-16 周）
  • 2026 新选项：图+向量一体库（HelixDB/Kuzu/CozoDB）省双组件；Neo4j LLM Graph Builder 文档→图；RAG-Anything 全模态入图
  • Agentic 铁律：先纯 RAG 跑通再加 Agent 外壳；仅模糊/多步问题路由进 Agent 管线；语义缓存+多模型策略降成本
