# 编译与确认流程

## 1. 流程

1. 统计 RAG 查询命中和未命中。
2. 将高频业务域加入编译候选。
3. AI 根据原文和知识对象起草页面。
4. 评审人检查规则、例外、来源和版本。
5. 业务 Owner 确认。
6. 页面变为 confirmed / active。
7. 更新 `_index.md` 与 `_domain-context.md`。

## 2. 状态

| 状态 | 含义 |
|---|---|
| draft | AI 起草或人工未确认 |
| reviewing | 评审中 |
| confirmed | 已确认 |
| conflict | 存在冲突 |
| deprecated | 已废弃 |

## 3. 拒绝条件

- 来源缺失。
- 例外场景未覆盖。
- 与当前基线冲突。
- 无法回溯知识对象或原文。
